# Production Estimating

This stage sits between an open JobNumber (agency-job-lifecycle) and client billing and supplier-invoice matching. It owns the Production Estimate (`Presupuesto de Producción`, also `Estimado`), its lines, the supplier quotation matrix, the chosen supplier per line, the production purchase order (`Orden de Compra de Producción`), client advance requests (`Anticipos`) and the Post Buy comparison. It never records a client approval without an authorized human, never issues or sends a PO, and never books a supplier or client invoice.

Read [control-contract.md](references/control-contract.md) first and apply it. Circuit map: [e2e-circuit.md](references/erp/e2e-circuit.md). Domain rules: [production.md](references/erp/production.md) (processes P01–P27, lifecycles §4.1–4.2, rules R1–R43 in §5, controls and exceptions §10.4–10.5, gaps 3, 4, 11, 12). Rule ids below are that document's §5 numbers.

## Use when
- Someone asks to "quote", "cotizar", or build a `presupuesto de producción` / `estimado` for audiovisual, print, digital, event or agency-internal work on an open JobNumber.
- Adding indirect lines, direct lines (`Dire`), agency-performed lines (supplier `0000`), cost-rendering lines (`rendición de costos`) or price-list lines (`lista de precios`).
- Collecting up to three supplier alternatives or a multi-quantity quotation (`Cotizar`), and preparing the award (`Adjudicar`) or chosen supplier (`Proveedor elegido`).
- Preparing client approval (`Aprobar por Cliente`), approval for billing (`Aprobar para Facturar`, total or per line), rejection/recovery, close/reopen, copy or void-and-replace (`Anula y Sustituye`).
- Drafting production POs, advance requests or the Post Buy initial-vs-current variance.

## Do not use when
- Opening a JobNumber or fixing typology/billing code → agency-job-lifecycle.
- Credit-limit policy, budget reserves or PO availability → agency-budget-control; client PO references and transfers → agency-contract-po.
- The estimate was generated by a fee contract (it is approved on the contract) → agency-fee-contracts.
- Supplier override-commission contracts and their monthly pendings → agency-rebates.
- Creative delivery, royalty contracts or event staff → agency-production.
- Booking the supplier invoice → agency-payables; issuing the client invoice → agency-client-billing; settling cost renderings → agency-expenses; collecting an advance → agency-collections.

## Required inputs
- **Blocking:** tenant, owner client, JobNumber and its state (vigent), billable flag, typology and billing code (`F`, `0`, `?`, `*`); estimate period (month/year) still open for loading.
- **Blocking:** production-type catalogue with flags (commissionable, `Preproducción` 999, `Regalías`, `Bonificada` 996, VAT category) and GL mapping; supplier master entries (type flags, payment term, in-conflict flag).
- **Blocking for client approval:** client credit limit, open AR and approved-unbilled amounts in one currency; whether the client accepts supplier commissions; approver identity and permission.
- Header data: approval type (`A Presupuestar` or `Preaprobado`), `% Serv. Agencia` and `% Bonif. Serv. Agencia`, payment terms, billing mode (`Junto` or `General`), client PO reference, split code for split-billing jobs.
- Line evidence: scope/specs, quantity, days, unit cost and price net of VAT, currency, reference FX from the host's rate source, supplier quotes with validity dates.
- Configuration flags: mandatory PO, mandatory PO approval, price lists by client/type, automatic initial version, cost-plus mode, creator-not-approver enforcement.
- Ask only for missing material inputs. Never ask for credentials in chat.

## Procedure
1. Validate the job. It must be open/vigent (R3). A generic or non-billable job carries cost only (R4); typologies N, S and W carry no sale value. Billing code `?` blocks client approval until a billing client exists; split jobs need billing clients and a split code with percentages (R7). The period must sit within ±36 months and outside closed periods (R1).
2. Build the header (P01, P15): approval type, agency service % and its discount, payment terms (default from client, R5), billing mode (R6), client PO reference, contact. `Nº Estimado` (monthly) and `Nº Presupuesto` (global) are assigned by the ERP (R2); never invent them.
3. Add lines by kind (P02–P06). Indirect: supplier invoices the agency. Direct: sale equals cost (R11). Agency-performed: supplier `0000`, no external PO (R17). Cost-rendering: special supplier plus an observation-code-84 account (P05). Price list: generic list first, then client list, valid version only (R66, R67). Enter cost and sale net of VAT (R8), one currency per line (R16).
4. Run `estimate_totals`. Resolve every blocker (`direct_sale_differs_from_cost`, `commission_on_internal_line`, `duplicate_line_id`) before going further. Record `invoice_groups`: one client invoice holds one currency (R16). Allow a supplier commission only when the agency feature is on and the client accepts it (R15).
5. Source suppliers. Keep up to three alternatives per line with cost and observations (R35, P11). For multi-quantity work use a `Preproducción` line and build the supplier × quantity matrix, optionally split into make-ready and run (P08). Draft an award recommendation (lowest price by default, trade-offs explained) but do not award before client approval (R36, P10).
6. Prepare the client-approval pack. Reject lines that will not proceed first, because approval covers the whole estimate (R29, P21). Run `credit_exposure` with this estimate's client total (R31). If `requires_override_approval` is true, return `blocked` and route the override to agency-budget-control. Note the Post Buy initial-version snapshot if configured (P17). Return `pending_approval` with the payload digest.
7. After a verified client approval, record the chosen supplier on every line with alternatives; without it no pending-to-receive exists and no supplier invoice can be entered (R35). Then prepare the award; a quoted `Fotocromía` value spawns a separate line (R18).
8. Draft POs (P25) from client-approved lines with a chosen supplier only: one estimate per PO (R37), direct and indirect never mixed (R38), foreign currency only where daily FX is managed (R39). State that issuance will lock supplier and cost (R24). Route to the PO approver when PO approval is mandatory (R40).
9. Draft advance requests (`Anticipos`) linked to estimate lines (P26), with states pending legalisation, pending collection, legalised. Hand collection to agency-collections.
10. Prepare approval for billing (P19), total or per delivered line, only for client-approved or pre-approved estimates and only with delivery evidence from agency-production. Lines pending billing approval cannot be invoiced (R33).
11. Handle changes (P12–P14, P21–P23). Check locks R20–R26 first. Prefer rejection to deletion; prefer Copy plus manual rejection to void-and-replace. A material change after approval invalidates the approval digest and needs fresh approval and PO headroom.
12. Build the Post Buy variance: initial version vs current per line, on cost and on sale. Flag sale decreases and cost increases beyond the agency tolerance.
13. Return artifacts. Mark a state as approved, ordered or invoiced only when a trusted ERP read confirms it.

## Rules and locks
- Lines invoiced to the client: sale, discount, agency service and supplier commission are immutable (R20). Lines invoiced by the supplier: supplier and cost are immutable (R21).
- A closed estimate allows no line edit or deletion (R22). The first line cannot be deleted (R23). A deleted line is recoverable only before saving (R26).
- An issued PO locks supplier and cost (R24). A PO linked to a supplier invoice cannot be voided or deleted until that invoice is deleted (month not pre-closed) or reversed by a credit note (R25).
- Disapproval by client is blocked once any line is approved for billing; disapproval for billing is blocked on invoiced lines (R32).
- Client approval needs `Aprueba por Cliente`, billing approval needs `Aprueba para Facturar`, PO approval needs `Aprueba Ordenes de Compra de Producción` (R27). The author does not approve (R28; enforcement is configurable in the reference, mandatory here).
- Mandatory PO and mandatory PO approval gate supplier-invoice entry (R40) (configurable).
- Production-department users never see unit sale or sale columns; keep those fields out of the model context for them (R42). Confidential supplier commissions are visible only to authorized roles.
- Reduced-VAT production types carry their rate through estimate, PO, supplier and client invoices (R41); rates come from the host tax configuration.
- Cost-plus pricing is assumed to be markup on cost (R13) (confirm locally). Whether agency service is computed before or after line discount, and how contingency (`imprevistos`) and creative-idea % enter totals, is unspecified (confirm locally); `estimate_totals` applies service to post-discount sale.
- The reference does not state the credit-exposure formula (confirm locally); the tool uses open AR + approved unbilled + request.

## Calculations
- `estimate_totals`: per line, sale = unit price × quantity × days less `discount_bps`; cost = unit cost × quantity × days; agency service on eligible non-direct lines = sale × `agency_service_bps` less `agency_service_discount_bps`; supplier commission fixed or % of cost; margin = sale − cost + service + commission (direct lines: service + commission only). Returns currency totals, `invoice_groups` and blockers.
- `credit_exposure`: before client approval, with `credit_limit_minor`, `ar_open_minor`, `approved_unbilled_minor` and `requested_minor` (the estimate's client total including service) in one currency.
- `allocate`: split an estimate total across billing clients of a split job using split-code percentages as integer weights (for example bps), conserving the total exactly.

- Not calculated by tools: VAT, perceptions and withholdings (host tax tables), FX rates, credit limits, price-list validity, override commissions (agency-rebates), PO-to-invoice tolerance (gap 12) and Post Buy tolerance (agency policy).

## Approvals and segregation of duties
- The producer or account executive prepares; a different authenticated user holding the matching permission records client approval (with client evidence such as a signed quote or client PO), approval for billing and PO approval.
- Bind each approval to the payload digest (computed by the host, for example with `payload_digest`) of action, tenant, client, JobNumber, estimate number and revision, line ids, currency totals and, for POs, supplier ids. Any material change invalidates it.
- A credit-limit override is a separate approval owned by finance. Sending quotes, RFQs or POs to suppliers is a send action and needs approval.

## Exceptions to escalate
- Lines with alternatives but no chosen supplier (blocks AP) → producer.
- Client-approved lines without a PO where PO is mandatory, or unapproved POs → PO approver.
- Credit exposure above limit → account director and finance via agency-budget-control.
- Supplier commission type "to define" left open → producer and controller.
- Sale value on a generic job or N/S/W typology; job closed while estimate open → account director (agency-job-lifecycle).
- Approved for billing but not invoiced beyond threshold → agency-client-billing; month-end accrual → agency-accruals-revaluation.
- Post Buy negative variance beyond tolerance → account director.
- Supplier in conflict (apocryphal-invoice register) or expired print authorization → AP and tax owner.
- Lines manually marked as invoiced (bypass of the automatic flow) → controller.
- Costed tasks not linked to any estimate (unbilled leakage) → account team.
- Overdue advances or open cost renderings → agency-collections or agency-expenses.

## Return and handoff
Return `estimate_draft`, `estimate_totals`, `supplier_comparison`, `client_approval_pack`, `purchase_order_drafts`, `post_buy_variance`. Include tenant, client and job IDs, JobNumber, estimate period/number and revision, line ids, currency totals, status (`draft`/`blocked`/`pending_approval`/`completed` only when verified), evidence references, blockers, approvals required and next stage.
**Owner:** Producer and account director. **Next:** agency-production, agency-client-billing, agency-payables.
